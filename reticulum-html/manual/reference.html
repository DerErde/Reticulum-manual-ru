Справочник API¶

Взаимодействие в сетях Reticulum осуществляется с помощью простого набора классов, предоставляемых API RNS. В этой главе перечислены и объяснены все классы, предоставляемые API сетевого стека Reticulum, а также их сигнатуры методов и способы использования. Её можно использовать как справочник при написании приложений, использующих Reticulum, или прочитать полностью, чтобы понять все возможности RNS с точки зрения разработчика.

Reticulum

class RNS.Reticulum(configdir=None, loglevel=None, logdest=None, verbosity=None, require_shared_instance=False, shared_instance_type=None)¶

Этот класс используется для инициализации доступа к Reticulum в программе. Вы должны создать ровно один экземпляр этого класса перед выполнением любых других операций RNS, таких как создание пунктов назначения или отправка трафика. Каждая независимо выполняемая программа должна создать свой собственный экземпляр класса Reticulum, но Reticulum автоматически обрабатывает межпрограммное взаимодействие в одной системе и также предоставляет все подключенные программы внешним интерфейсам.

Как только создается экземпляр этого класса, Reticulum начинает открывать и настраивать любые аппаратные устройства, указанные в предоставленной конфигурации.

В настоящее время первый запущенный экземпляр должен продолжать работать, пока подключены другие локальные экземпляры, поскольку первый созданный экземпляр действует как главный экземпляр, который напрямую взаимодействует с внешним оборудованием, таким как модемы, TNC и радиостанции. Если главному экземпляру дается команда завершить работу, он не завершится, пока не завершатся все клиентские процессы (если только не будет принудительно остановлен).

Если вы запускаете Reticulum в системе с несколькими различными программами, использующими RNS, которые запускаются и завершаются в разное время, будет полезно запустить главный экземпляр RNS в качестве демона для использования другими программами по требованию.

MTU = 500¶

MTU, которого придерживается Reticulum и соблюдения которого ожидает от других участников. По умолчанию MTU составляет 500 байт. В пользовательских реализациях сети RNS это значение можно изменить, но это полностью нарушит совместимость со всеми другими сетями RNS. Одинаковый MTU является обязательным условием для взаимодействия участников в одной сети.

Если вы точно не знаете, что делаете, MTU следует оставить со значением по умолчанию.

LINK_MTU_DISCOVERY = True¶

Включено ли автоматическое определение MTU канала по умолчанию в этом выпуске. Определение MTU канала значительно увеличивает пропускную способность на быстрых каналах, но требует, чтобы все промежуточные узлы также его поддерживали. Поддержка этой функции была добавлена в версии RNS 0.9.0. В ближайшем будущем эта опция будет включена по умолчанию. Пожалуйста, обновите ваши экземпляры RNS.

ANNOUNCE_CAP = 2¶

Максимальный процент пропускной способности интерфейса, который в любой момент времени может быть использован для распространения объявлений. Если объявление было запланировано для передачи через интерфейс, но это привело бы к превышению разрешенного лимита пропускной способности, объявление будет поставлено в очередь на передачу, когда появится доступная пропускная способность.

Reticulum всегда отдает приоритет распространению объявлений с меньшим количеством переходов, гарантируя, что крупные удаленные сети с множеством участников на быстрых каналах не перегрузят пропускную способность меньших сетей на более медленных средах. Если объявление остается в очереди в течение длительного времени, оно в конечном итоге будет отброшено.

Это значение будет применяться по умолчанию ко всем созданным интерфейсам, но может быть настроено индивидуально для каждого интерфейса. В целом, глобальную настройку по умолчанию изменять не следует, а любые изменения следует вносить только на уровне отдельных интерфейсов.

MINIMUM_BITRATE = 5¶

Минимальная скорость передачи данных, необходимая в среде, чтобы Reticulum мог успешно устанавливать соединения. В настоящее время 5 бит в секунду.

static should_use_implicit_proof()¶

Возвращает информацию о том, являются ли отправляемые подтверждения явными или неявными.

Возвращает:

True, если текущая работающая конфигурация предписывает использовать неявные подтверждения. False, если нет.

static transport_enabled()¶

Возвращает информацию о том, включен ли транспорт для работающего экземпляра.

Когда транспорт включен, Reticulum будет маршрутизировать трафик для других участников, отвечать на запросы пути и передавать объявления по сети.

Возвращает:

True, если транспорт включен, False, если нет.

static link_mtu_discovery()¶

Возвращает информацию о том, включено ли определение MTU канала для работающего экземпляра.

Когда определение MTU канала включено, Reticulum будет автоматически увеличивать MTU каналов до максимального поддерживаемого значения, повышая скорость и эффективность передачи.

Возвращает:

True, если определение MTU канала включено, False, если нет.

static remote_management_enabled()¶

Возвращает информацию о том, включено ли удаленное управление для работающего экземпляра.

Когда удаленное управление включено, аутентифицированные участники могут удаленно запрашивать и управлять этим экземпляром.

Возвращает:

True, если удаленное управление включено, False, если нет.

Identity

class RNS.Identity(create_keys=True)¶

Этот класс используется для управления идентификаторами в Reticulum. Он предоставляет методы для шифрования, дешифрования, подписи и проверки, а также является основой для всей зашифрованной связи в сетях Reticulum.

Параметры:

create_keys – Указывает, следует ли генерировать новые ключи шифрования и подписи.

CURVE = 'Curve25519'¶

Кривая, используемая для обмена ключами по протоколу Диффи-Хеллмана на эллиптической кривой

KEYSIZE = 512¶

Размер ключа X.25519 в битах. Полный ключ представляет собой конкатенацию 256-битного ключа шифрования и 256-битного ключа подписи.

RATCHETSIZE = 256¶

Размер ключа обновления (ratchet key) X.25519 в битах.

RATCHET_EXPIRY = 2592000¶

Срок действия полученных ключей обновления (ratchets) в секундах, по умолчанию 30 дней. Reticulum всегда будет использовать последний объявленный ключ обновления и сохранять его в течение RATCHET_EXPIRY с момента получения, после чего он будет отброшен. Если за это время будет объявлен более новый ключ обновления, он заменит уже известный.

TRUNCATED_HASHLENGTH = 128¶

Константа, определяющая длину усеченного хеша (в битах), используемую Reticulum для адресуемых хешей и других целей. Не настраивается.

static recall(target_hash, from_identity_hash=False, _no_use=False)¶

Извлекает идентификатор (identity) по хешу пункта назначения или самого идентификатора. По умолчанию эта функция возвращает идентификатор, связанный с указанным хешем пункта назначения (destination). Например, если вы знаете хеш пункта назначения lxmf.delivery для конечной точки, эта функция вернет связанный с ним базовый идентификатор. Вы также можете искать идентификатор по известному хешу идентификатора, установив аргумент from_identity_hash.

Параметры:

  • target_hash – Хеш пункта назначения или идентификатора в виде bytes.

  • from_identity_hash – Искать ли по хешу идентификатора вместо хеша пункта назначения, в виде bool.

Возвращает:

Экземпляр RNS.Identity, который можно использовать для создания исходящего RNS.Destination, или None, если пункт назначения неизвестен.

static recall_app_data(destination_hash, _no_use=False)¶

Извлекает последние полученные app_data для указанного хеша пункта назначения.

Параметры:

destination_hash – Хеш пункта назначения в виде bytes.

Возвращает:

Bytes, содержащие app_data, или None, если пункт назначения неизвестен.

Параметры:

Destination

class RNS.Destination(identity, direction, type, app_name, *aspects)¶

Класс, используемый для описания конечных точек в сети Reticulum. Экземпляры Destination используются как для создания исходящих, так и входящих конечных точек. Тип пункта назначения определяет, будет ли использоваться шифрование, и какой тип, при взаимодействии с конечной точкой. Пункт назначения также может объявить о своем присутствии в сети, что приведет к распространению необходимых ключей для зашифрованной связи с ним.

Параметры:

  • identity – Экземпляр RNS.Identity. Может содержать только открытые ключи для исходящего пункта назначения или закрытые ключи для входящего.

  • direction – RNS.Destination.IN или RNS.Destination.OUT.

  • type – RNS.Destination.SINGLE, RNS.Destination.GROUP или RNS.Destination.PLAIN.

  • app_name – Строка, определяющая имя приложения.

  • *aspects – Любое ненулевое количество строковых аргументов.

RATCHET_COUNT = 512¶

Количество сгенерированных ключей обновления (ratchet keys) по умолчанию, которое будет хранить пункт назначения, если у него включены ключи обновления.

RATCHET_INTERVAL = 1800¶

Минимальный интервал между сменой ключей обновления (ratchet keys) в секундах.

announce(app_data=None, path_response=False, attached_interface=None, tag=None, send=True)¶

Создает пакет объявления для этого пункта назначения и транслирует его на всех соответствующих интерфейсах. К объявлению можно добавить данные, специфичные для приложения.

Параметры:

  • app_data – Bytes, содержащие app_data.

  • path_response – Внутренний флаг, используемый RNS.Transport. Не обращайте внимания.

accepts_links(accepts=None)¶

Устанавливает или запрашивает, принимает ли пункт назначения входящие запросы на установку связи (link requests).

Параметры:

accepts – Если True или False, этот метод устанавливает, принимает ли пункт назначения входящие запросы на установку связи. Если не указано или None, метод возвращает, принимает ли пункт назначения запросы на установку связи в данный момент.

Возвращает:

True или False в зависимости от того, принимает ли пункт назначения входящие запросы на установку связи, если параметр accepts не указан или None.

set_link_established_callback(callback)¶

Регистрирует функцию, которая будет вызвана, когда с этим пунктом назначения будет установлена связь (link).

Параметры:

callback – Функция или метод с сигнатурой callback(link), которая будет вызвана при установлении новой связи с этим пунктом назначения.

set_packet_callback(callback)¶

Регистрирует функцию, которая будет вызвана, когда этим пунктом назначения будет получен пакет.

Параметры:

callback – Функция или метод с сигнатурой callback(data, packet), которая будет вызвана, когда этот пункт назначения получит пакет.

set_proof_requested_callback(callback)¶

Регистрирует функцию, которая будет вызвана, когда для пакета, отправленного этому пункту назначения, будет запрошено подтверждение (proof). Позволяет контролировать, когда и следует ли отправлять подтверждения для полученных пакетов.

Параметры:

callback – Функция или метод с сигнатурой callback(packet), которая будет вызвана при получении пакета, запрашивающего подтверждение. Функция обратного вызова должна возвращать True или False. Если возвращается True, подтверждение будет отправлено. Если False — подтверждение отправлено не будет.

set_proof_strategy(proof_strategy)¶

Устанавливает стратегию подтверждения для пункта назначения.

Параметры:

proof_strategy – Одно из: RNS.Destination.PROVE_NONE, RNS.Destination.PROVE_ALL или RNS.Destination.PROVE_APP. Если установлено RNS.Destination.PROVE_APP, для определения необходимости отправки подтверждения будет вызван proof_requested_callback.

  • auto_compress – Если True или False, определяет, следует ли выполнять автоматическое сжатие ответов. Если задано целочисленное значение, ответы будут автоматически сжиматься, только если их размер меньше этого значения в байтах. Если не указано, будут использоваться настройки сжатия по умолчанию.

enable_ratchets(ratchets_path)¶

Включает ключи обновления (ratchets) для пункта назначения. Когда ключи обновления включены, Reticulum будет автоматически менять ключи, используемые для шифрования пакетов этому пункту назначения, и включать последний ключ обновления в объявления.

Включение ключей обновления для пункта назначения обеспечит прямую секретность (forward secrecy) для пакетов, отправляемых этому пункту назначения, даже если они отправляются вне Link. Обычная процедура установления связи Reticulum Link уже выполняет собственный обмен эфемерными ключами при каждой установке связи, что означает, что ключи обновления не являются необходимыми для обеспечения прямой секретности для каналов связи.

Включение ключей обновления незначительно повлияет на размер объявления, добавляя 32 байта к каждому отправляемому объявлению.

Параметры:

ratchets_path – Путь к файлу для хранения данных ключей обновления.

Возвращает:

True, если операция выполнена успешно, иначе False.

Packet

class RNS.Packet(destination, data, create_receipt=True)¶

Класс Packet используется для создания экземпляров пакетов, которые могут быть отправлены по сети Reticulum. Пакеты будут автоматически зашифрованы, если они адресованы пункту назначения RNS.Destination.SINGLE, RNS.Destination.GROUP или RNS.Link.

Для пунктов назначения RNS.Destination.GROUP Reticulum будет использовать предварительно согласованный ключ, настроенный для данного пункта назначения. Все пакеты для групповых пунктов назначения шифруются одним и тем же ключом AES-256.

Для пунктов назначения RNS.Destination.SINGLE Reticulum будет использовать новый производный эфемерный ключ AES-256 для каждого пакета.

Для пунктов назначения RNS.Link Reticulum использует эфемерные ключи для каждого канала и обеспечивает прямую секретность (Forward Secrecy).

Параметры:

  • destination – Экземпляр RNS.Destination, которому будет отправлен пакет.

  • data – Полезная нагрузка данных, включаемая в пакет, в виде bytes.

  • create_receipt – Указывает, следует ли создавать RNS.PacketReceipt при создании экземпляра пакета.

Channel

class RNS.Channel.Channel¶

Обеспечивает надежную доставку сообщений по каналу.

Channel отличается от Request и Resource несколькими важными особенностями:

Непрерывный (Continuous)

Сообщения могут отправляться или приниматься, пока открыт Link.

Двунаправленный (Bi-directional)

Сообщения могут отправляться в любом направлении по Link; ни один из концов не является клиентом или сервером.

Ограниченный по размеру (Size-constrained)

Сообщения должны быть закодированы в один пакет.

Channel похож на Packet, за исключением того, что он обеспечивает надежную доставку (автоматические повторные попытки), а также структуру для обмена несколькими типами сообщений по Link.

Channel не создается напрямую, а получается из Link с помощью get_channel().
