Наверх

Быстрый старт¶

Лучший способ начать работу с сетевым стеком Reticulum зависит от того, что вы хотите делать. Это руководство описывает разумные начальные пути для различных сценариев.

Автономная установка Reticulum¶

Если вы просто хотите установить Reticulum и связанные с ним утилиты в системе, самый простой способ — через менеджер пакетов pip:

pip install rns

Если у вас ещё не установлен pip, вы можете установить его с помощью менеджера пакетов вашей системы командой, такой как sudo apt install python3-pip, sudo pamac install python-pip или подобной.

Вы также можете загрузить релизные wheel-файлы Reticulum с GitHub или из других каналов и установить их офлайн с помощью pip:

pip install ./rns-1.1.2-py3-none-any.whl

На платформах, ограничивающих установку пользовательских пакетов через pip, возможно, потребуется вручную разрешить это, используя флаг командной строки --break-system-packages при установке. Это на самом деле не сломает никакие пакеты, если только вы не устанавливали Reticulum напрямую через менеджер пакетов вашей операционной системы.

pip install rns --break-system-packages

Для более подробных инструкций по установке, пожалуйста, смотрите раздел Примечания по установке для конкретных платформ.

После завершения установки может быть полезно обратиться к главе Использование Reticulum в вашей системе.

Решение проблем с зависимостями и установкой¶

На некоторых платформах бинарные пакеты для всех зависимостей могут быть недоступны, и установка через pip может завершиться ошибкой. В таких случаях проблему обычно можно решить, установив пакеты для разработки для вашей платформы:

# Debian / Ubuntu / Производные
sudo apt install build-essential

# Arch / Manjaro / Производные
sudo pamac install base-devel

# OpenSuse 
sudo zypper install -t pattern devel_basis

# Fedora
sudo dnf groupinstall "Development Tools" "Development Libraries"

С установленными базовыми пакетами для разработки pip сможет скомпилировать любые отсутствующие зависимости из исходников и завершить установку даже на платформах, где нет предварительно скомпилированных пакетов.

Попробуйте использовать программу на основе Reticulum¶

Если вы просто хотите попробовать использовать программу, созданную с помощью Reticulum, существует ряд различных программ, которые обеспечивают базовую связь и различные другие полезные функции, даже в сетях Reticulum с крайне низкой пропускной способностью.

Использование встроенных утилит¶

В состав Reticulum входит ряд утилит, которые упрощают управление вашей сетью, проверку подключения и делают Reticulum доступным для других программ в вашей системе.

Вы можете использовать rnsd для запуска Reticulum в качестве фоновой или активной службы, а утилиты rnstatus, rnpath и rnprobe — для просмотра и запроса состояния сети и подключений.

Чтобы узнать больше об этих служебных программах, загляните в главу Использование Reticulum в вашей системе этого руководства.

Создание сети с помощью Reticulum¶

Для создания сети вам нужно указать один или несколько интерфейсов для использования Reticulum. Это делается в конфигурационном файле Reticulum, который по умолчанию находится в ~/.reticulum/config. Вы можете получить пример конфигурационного файла со всеми опциями через rnsd --exampleconfig.

При первом запуске Reticulum создаст конфигурационный файл по умолчанию с одним активным интерфейсом. Этот интерфейс по умолчанию использует ваши существующие сети Ethernet и WiFi (если есть) и позволяет вам общаться только с другими узлами Reticulum в пределах вашей локальной широковещательной сети.

Для дальнейшей связи вам нужно будет добавить один или несколько интерфейсов. Конфигурация по умолчанию включает ряд примеров, от использования TCP через интернет до интерфейсов LoRa и пакетной радиосвязи.

С Reticulum вам нужно только настроить, через какие интерфейсы вы хотите общаться. Нет необходимости настраивать адресные пространства, подсети, таблицы маршрутизации или что-то ещё, к чему вы, возможно, привыкли в сетях других типов.

Как только Reticulum узнает, какие интерфейсы следует использовать, он автоматически определит топологию и настроит передачу данных к любым известным ему назначениям.

В ситуациях, когда у вас уже есть устоявшаяся сеть WiFi или Ethernet и множество устройств, желающих использовать одни и те же внешние пути сети Reticulum (например, через LoRa), часто будет достаточно позволить одной системе действовать как шлюз Reticulum, добавив любые внешние интерфейсы в конфигурацию этой системы и затем включив на ней транспорт. Любое другое устройство в вашей локальной WiFi-сети сможет подключиться к этой более широкой сети Reticulum, просто используя конфигурацию по умолчанию (AutoInterface).

Возможно, примеров в конфигурационном файле достаточно, чтобы вы начали. Если вам нужно больше информации, вы можете прочитать главы Построение сетей и Интерфейсы этого руководства, но что наиболее важно, начните с прочтения следующего раздела, Начальная настройка подключения, так как он даёт наиболее важное понимание того, как обеспечить надёжное подключение с минимумом обслуживания.

Начальная настройка подключения¶

Reticulum — это не услуга, на которую вы подписываетесь, и не единая глобальная сеть, к которой вы «присоединяетесь». Это сетевой стек; набор инструментов для построения коммуникационных систем, которые соответствуют вашим конкретным ценностям, требованиям и условиям эксплуатации. Способ подключения к другим узлам Reticulum — полностью ваш выбор.

Один из самых мощных аспектов Reticulum заключается в том, что он предоставляет множество инструментов для установления, поддержания и оптимизации подключения. Вы можете использовать эти инструменты изолированно или комбинировать их в сложных конфигурациях для достижения широкого спектра целей.

Будь то создание полностью частной, изолированной сети для вашей семьи; построение устойчивой общественной ячеистой сети, которая переживёт разрушение инфраструктуры; подключение как можно дальше и шире к как можно большему числу узлов; или просто поддержание надёжной, зашифрованной связи с конкретной организацией, которая вам важна, Reticulum предоставляет механизмы для этого.

Нет «правильного» или «неправильного» способа построить сеть Reticulum, и вам не нужно быть сетевым инженером, чтобы начать. Если информация передаётся так, как вы задумали, и ваши требования к конфиденциальности и безопасности соблюдены, ваша конфигурация успешна. Reticulum разработан, чтобы сделать самые сложные и трудные сценарии достижимыми, даже когда другие сетевые технологии терпят неудачу.

Поиск вашего пути¶

Когда вы впервые начинаете использовать Reticulum, вам нужен способ подключиться к узлам, с которыми вы хотите общаться — процесс начальной настройки подключения.

Важно

Распространённая ошибка в современных сетях — опора на несколько централизованных, жёстко заданных точек входа. Если каждый пользователь просто подключается к одному и тому же списку публичных IP-адресов, найденных на веб-сайте, сеть становится хрупкой, централизованной и в конечном счёте не выполняет обещание децентрализации и отказоустойчивости. Здесь на вас лежит ответственность.

Reticulum поощряет подход органического роста. Вместо того, чтобы полагаться на постоянные статические подключения к удалённым серверам, вы можете использовать временные начальные подключения для непрерывного обнаружения более подходящей или локальной инфраструктуры. После обнаружения ваша система может автоматически формировать более сильные, прямые связи с этими узлами и отбрасывать временные начальные связи. Это приводит к сети соединений, которые географически релевантны, устойчивы и эффективны.

Можно просто добавить несколько публичных точек входа в раздел [interfaces] вашей конфигурации Reticulum и быть на связи, но лучший вариант — включить обнаружение интерфейсов и либо вручную выбирать релевантные, локальные интерфейсы, либо включить автоматическое подключение к обнаруженным интерфейсам.

Релевантной опцией в этом контексте является опция интерфейса только для начальной загрузки (bootstrap only). Это автоматизированный инструмент для лучшего распределения подключений. Включив обнаружение интерфейсов и автоматическое подключение, и пометив интерфейс как bootstrap_only, вы даёте Reticulum указание использовать этот интерфейс в первую очередь для поиска вариантов подключения, а затем отключить его, как только будет обнаружено достаточное количество точек входа. Это помогает создать топологию сети, которая предпочитает локальность и устойчивость простой централизации, вызванной использованием лишь нескольких статических точек входа.

Хорошими местами для поиска определений интерфейсов для начальной настройки подключения являются такие сайты, как directory.rns.recipes и rmap.world.

Создание персональной инфраструктуры¶

Вам не нужен центр обработки данных, чтобы быть значимой частью экосистемы Reticulum. На самом деле, самые важные узлы в сети часто являются самыми маленькими.

Мы настоятельно рекомендуем всем, даже домашним пользователям, мыслить категориями построения персональной инфраструктуры. Не подключайте каждый телефон, планшет и компьютер в вашем доме напрямую к публичному интернет-шлюзу. Вместо этого используйте старый компьютер, Raspberry Pi или поддерживаемый роутер в качестве собственного, персонального Транспортного Узла:

  • Ваш локальный Транспортный Узел находится у вас дома, подключён к вашей WiFi и, возможно, радиоинтерфейсу (например, RNode).

  • Вы настраиваете этот узел с интерфейсом bootstrap_only (возможно, TCP-туннель к более широкой сети) и включаете обнаружение интерфейсов.

  • Пока вы спите, работаете или готовите, ваш узел слушает сеть. Он обнаруживает других членов локального сообщества, проверяет их Сетевые Идентичности и автоматически устанавливает прямые соединения.

  • Теперь ваши персональные устройства подключаются к вашему локальному узлу, который интегрирован в живую, дышащую локальную mesh-сеть. Ваш трафик проходит по локальным маршрутам, предоставленным другими реальными людьми из сообщества, а не перебрасывается через удалённый сервер.

Не ждите, пока другие построят сети, которые вы хотите видеть. Каждая сеть важна, и возможно, наиболее важны те, которые поддерживают семьи и отдельных людей. Когда появится достаточно такой личной, локальной инфраструктуры, прямое соединение их друг с другом, без прохождения через публичный Интернет, станет неизбежным.

Комбинирование стратегий¶

Нет требования придерживаться одной стратегии. Самые надёжные конфигурации часто смешивают статические, динамические и обнаруженные интерфейсы.

  • Статические Интерфейсы: Вы поддерживаете постоянный интерфейс с доверенным другом или организацией, используя статическую конфигурацию.

  • Начальные Связи (Bootstrap Links): Вы подключаете интерфейс bootstrap_only к публичному шлюзу в Интернете для поиска новых доступных для подключения узлов или для восстановления связи, если другие ваши интерфейсы откажут.

  • Локальная связь на больших расстояниях: Вы запускаете RNodeInterface на общей частоте, что даёт вам полностью приватный доступ на большие расстояния как к собственной сети, так и к другим узлам Reticulum по всему миру, без возможности для каких-либо «поставщиков услуг» контролировать или отслеживать, как вы взаимодействуете с людьми.

Комбинируя эти методы, вы создаёте систему, устойчивую к единым точкам отказа, адаптируемую к изменяющимся сетевым условиям и лучше интегрированную в вашу физическую и социальную реальность.

Работоспособность сети и ответственность¶

Участвуя в более широких сетях, которые вы обнаруживаете и строите, вы неизбежно столкнётесь с узлами, которые неправильно настроены, вредоносны или просто сломаны. Чтобы защитить свои ресурсы и ресурсы ваших соседей, вы можете использовать систему Публикации чёрных списков [Blackhole Management].

Будь то ручная блокировка спамящего узла или подписка на чёрный список от доверенного участника сети — эти инструменты помогают гарантировать, что ваша транспортная пропускная способность используется для связи, которую вы считаете легитимной. Это сохраняет эффективность вашего локального сегмента и способствует здоровью более широкой сети.

Вклад в глобальную сеть Ret¶

Если у вас есть возможность поддерживать стабильный узел с публичным IP-адресом, подумайте о том, чтобы стать Публичной Точкой Входа. Опубликовав свой интерфейс как обнаруживаемый, вы предоставляете потенциальную точку подключения для других, помогая сети расти и достигать новых областей.

Руководство по правильной настройке публичной точки входа смотрите в разделе Размещение публичных точек входа.

Подключение к распределенной магистральной сети¶

Глобальная, распределённая магистральная сеть из Транспортных Узлов Reticulum управляется добровольцами со всего мира. Эта сеть представляет собой гетерогенную совокупность как публичных, так и частных узлов, которые формируют нескоординированную, добровольную магистраль межсетевого взаимодействия, в настоящее время обеспечивающую глобальные транспортные и межсетевые возможности для Reticulum.

В качестве хорошей отправной точки вы можете найти определения интерфейсов для подключения ваших собственных сетей к этой магистрали на таких сайтах, как directory.rns.recipes и rmap.world.

Совет

Не полагайтесь только на одно подключение к распределённой магистрали для повседневного использования. Гораздо лучше иметь настроенными несколько избыточных подключений и включить опции обнаружения интерфейсов, чтобы ваши узлы могли непрерывно находить возможности для пиринга по мере развития сети. Обратитесь к разделу Начальная настройка подключения для понимания опций.

Размещение публичных точек входа¶

Если вы хотите помочь построить сильную глобальную магистраль межсетевого взаимодействия, вы можете разместить публичную (или частную) точку входа в сеть Reticulum через Интернет. Этот раздел предлагает несколько полезных советов. Как только вы настроите свою публичную точку входа, отличной идеей будет сделать её обнаруживаемой через Reticulum.

Вам понадобится машина, физическая или виртуальная, с публичным IP-адресом, доступная для других устройств в Интернете.

Наиболее эффективный и производительный способ разместить точку входа, поддерживающую множество пользователей, — использовать BackboneInterface. Этот тип интерфейса полностью совместим с типами TCPClientInterface и TCPServerInterface, но намного быстрее и использует меньше системных ресурсов, позволяя вашему устройству обрабатывать тысячи подключений даже на маленьких системах.

Также важно установить ваш подключаемый интерфейс в режим gateway (шлюз), так как это значительно улучшит время схождения сети и нахождения путей для всех, кто подключается к вашей точке входа.

# Этот пример демонстрирует магистральный интерфейс (Backbone),
# настроенный для работы в качестве шлюза для подключения
# пользователей к публичной или частной сети

[[Public Gateway]]
  type = BackboneInterface
  enabled = yes
  mode = gateway
  listen_on = 0.0.0.0
  port = 4242

  # На публично доступных интерфейсах может
  # быть хорошей идеей настроить разумные
  # целевые показатели частоты объявлений.
  announce_rate_target = 3600
  announce_rate_penalty = 3600
  announce_rate_grace = 12

Если вместо этого вы хотите создать частную точку входа из Интернета, вы можете использовать опции IFAC (имя сети и парольная фраза) для защиты вашего интерфейса с помощью имени сети и парольной фразы.

# Частная точка входа, требующая предварительно согласованные
# имя сети и парольную фразу для подключения.

[[Private Gateway]]
  type = BackboneInterface
  enabled = yes
  mode = gateway
  listen_on = 0.0.0.0
  port = 4242
  network_name = private_ret
  passphrase = 2owjajquafIanPecAc

Если вы размещаете точку входа на операционной системе, которая не поддерживает BackboneInterface, вы можете использовать вместо этого TCPServerInterface, хотя он и будет менее производительным.

Соединение экземпляров Reticulum через Интернет¶

В настоящее время Reticulum предлагает три интерфейса, подходящих для соединения экземпляров через Интернет: Backbone, TCP и I2P. Каждый интерфейс предлагает различный набор функций, и пользователям Reticulum следует тщательно выбирать интерфейс, который наилучшим образом соответствует их потребностям.

TCPServerInterface позволяет пользователям размещать экземпляр, доступный через TCP/IP. Этот метод, как правило, быстрее, с меньшей задержкой и более энергоэффективен, чем использование I2PInterface, однако он также раскрывает больше данных о сервере-хосте.

BackboneInterface — это очень быстрый и эффективный тип интерфейса, доступный в операционных системах POSIX, разработанный для одновременной обработки тысяч соединений с низкими накладными расходами на память, обработку и ввод-вывод. Он полностью совместим с типами интерфейсов на основе TCP.

TCP-соединения раскрывают IP-адрес как вашего экземпляра, так и сервера любому, кто может проверить соединение. Кто-то может использовать эту информацию для определения вашего местоположения или личности. Противники, проверяющие ваши пакеты, могут записать метаданные пакетов, такие как время передачи и размер пакета. Даже если Reticulum шифрует трафик, TCP этого не делает, поэтому противник может использовать проверку пакетов, чтобы узнать, что система работает под управлением Reticulum, и какие другие IP-адреса к ней подключаются. Размещение публично доступного экземпляра через TCP также требует публично доступного IP-адреса, который некоторые провайдеры не предлагают [речь о размещении публичного узла в свой локальной сети].

I2PInterface направляет сообщения через Протокол Невидимого Интернета (I2P). Для использования этого интерфейса пользователи также должны запускать демон I2P параллельно с rnsd. Для постоянно работающих узлов I2P рекомендуется использовать i2pd.

По умолчанию I2P будет шифровать и смешивать весь трафик, отправляемый через Интернет, и скрывать IP-адреса как отправляющего, так и принимающего экземпляра Reticulum. Запуск узла I2P также будет ретранслировать зашифрованные пакеты других пользователей I2P, что будет использовать дополнительную пропускную способность и вычислительную мощность, но также значительно усложняет атаки по времени и другие формы глубокой проверки пакетов.

I2P также позволяет пользователям размещать глобально доступные экземпляры Reticulum с непубличных IP-адресов, за брандмауэрами и NAT.

В целом, рекомендуется использовать узел I2P, если вы хотите разместить публично доступный экземпляр с сохранением анонимности. Если для вас важнее производительность и немного более простая настройка, используйте TCP.

Добавление радиоинтерфейсов¶

После установки и настройки Reticulum вы можете добавить радиоинтерфейсы с любым совместимым оборудованием, которое у вас есть. Reticulum поддерживает широкий спектр радиооборудования, и если у вас уже есть что-то доступное, очень вероятно, что оно будет работать с Reticulum. Для получения информации о том, как это настроить, смотрите раздел Интерфейсы этого руководства.

Если у вас ещё нет доступного приёмопередающего оборудования, вы можете легко и дёшево собрать RNode — универсальный цифровой радиотрансивер дальнего радиуса действия, который легко интегрируется с Reticulum.

Чтобы собрать его самостоятельно, требуется установить специальную прошивку на поддерживаемую плату разработки LoRa с помощью скрипта автоустановки или веб-прошивальщика. Пожалуйста, смотрите главу Коммуникационное оборудование в этом руководстве. Если вы предпочитаете приобрести готовое устройство, вы можете обратиться к списку поставщиков.

Другие радиоаппаратные интерфейсы разрабатываются и становятся доступны благодаря широкому сообществу Reticulum. Вы можете найти больше информации по таким темам через системы обмена информацией на основе Reticulum.

Если у вас есть коммуникационное оборудование, которое ещё не поддерживается ни одним из существующих типов интерфейсов, вы можете легко написать (и, при желании, опубликовать) пользовательский модуль интерфейса, который сделает его совместимым с Reticulum.

Создание и использование пользовательских интерфейсов¶

Хотя Reticulum включает гибкий и широкий спектр встроенных интерфейсов, они не охватывают все мыслимые типы коммуникационного оборудования, которое Reticulum потенциально может использовать для связи.

Поэтому вы можете легко написать собственные модули интерфейсов, которые загружаются во время работы и используются наравне со встроенными типами интерфейсов.

Для получения дополнительной информации по этой теме и примеров кода, пожалуйста, смотрите главу Настройка интерфейсов.

Разработка программы с использованием Reticulum¶

Если вы хотите разрабатывать программы, использующие Reticulum, самый простой способ начать — установить последнюю версию Reticulum через pip:

pip install rns

Приведённая выше команда установит Reticulum и зависимости, и вы будете готовы импортировать и использовать RNS в своих программах. Следующим шагом, скорее всего, будет ознакомление с некоторыми Примерами программ.

Весь API Reticulum документирован в главе Справочник API этого руководства. Прежде чем погружаться, вероятно, хорошей идеей будет прочитать это руководство полностью, но как минимум начните с главы Понимание Reticulum.

Примечания по установке для конкретных платформ¶

Некоторые платформы требуют немного другой процедуры установки или имеют различные особенности, о которых стоит знать. Они перечислены здесь.

Android¶

Reticulum можно использовать на Android разными способами. Самый простой способ начать — использовать приложение, такое как Sideband.

Для большего контроля и возможностей вы можете использовать Reticulum и связанные с ним программы через приложение Termux, на момент написания доступное на F-droid.

Termux — это эмулятор терминала и среда Linux для устройств на базе Android, которая включает возможность использования множества различных программ и библиотек, включая Reticulum.

Для использования Reticulum в среде Termux вам необходимо установить python и библиотеку python-cryptography с помощью pkg, менеджера пакетов, встроенного в Termux. После этого вы можете использовать pip для установки Reticulum.

Из среды Termux выполните следующее:

# Сначала убедитесь, что индексы и пакеты обновлены.
pkg update
pkg upgrade

# Затем установите python и библиотеку cryptography.
pkg install python python-cryptography

# Убедитесь, что pip обновлён, и установите модуль wheel.
pip install wheel pip --upgrade

# Установите Reticulum
pip install rns

Если по какой-то причине пакет python-cryptography недоступен для вашей платформы через менеджер пакетов Termux, вы можете попытаться собрать его локально на вашем устройстве с помощью следующих команд:

# Сначала убедитесь, что индексы и пакеты обновлены.
pkg update
pkg upgrade

# Затем установите зависимости для библиотеки cryptography.
pkg install python build-essential openssl libffi rust

# Убедитесь, что pip обновлён, и установите модуль wheel.
pip install wheel pip --upgrade

# Чтобы позволить установщику собрать модуль cryptography,
# нужно сообщить ему, для какой платформы мы компилируем:
export CARGO_BUILD_TARGET="aarch64-linux-android"

# Запустите процесс установки модуля cryptography.
# В зависимости от вашего устройства это может занять несколько минут,
# так как модуль должен быть скомпилирован локально на вашем устройстве.
pip install cryptography

# Если установка выше прошла успешно, теперь вы можете установить
# Reticulum и любое связанное с ним программное обеспечение
pip install rns

Также возможно включить Reticulum в приложения, скомпилированные и распространяемые как Android APK. Подробный учебник и примеры исходного кода будут добавлены сюда позже. До тех пор вы можете использовать исходный код Sideband в качестве примера и отправной точки.

ARM64¶

На некоторых архитектурах, включая ARM64, не для всех зависимостей есть предварительно скомпилированные бинарные файлы. В таких системах вам может потребоваться установить python3-dev (или аналогичный) перед установкой Reticulum или программ, зависящих от Reticulum.

# Установите Python и пакеты для разработки
sudo apt update
sudo apt install python3 python3-pip python3-dev

# Установите Reticulum
python3 -m pip install rns

С установленными пакетами pip сможет собрать любые недостающие зависимости локально в вашей системе.

Debian Bookworm¶

В версиях Debian, выпущенных после апреля 2023 года, по умолчанию больше нельзя использовать pip для установки пакетов в вашу систему. К сожалению, вам придётся использовать вместо этого заменяющую команду pipx, которая размещает установленные пакеты в изолированной среде. Это не должно негативно повлиять на Reticulum, но не будет работать для включения и использования Reticulum в ваших собственных скриптах и программах. 

# Установите pipx
sudo apt install pipx

# Сделайте установленные программы доступными из командной строки
pipx ensurepath

# Установите Reticulum
pipx install rns

Для восстановления нормального поведения pip, создайте или отредактируйте конфигурационный файл, расположенный в ~/.config/pip/pip.conf, и добавив следующий раздел:

[global]
break-system-packages = true

Для одноразовой установки Reticulum, без глобального включения параметра break-system-packages вы можете использовать следующую команду:

pip install rns --break-system-packages

Примечание

Директива --break-system-packages — это несколько неудачный выбор слов. Её установка, конечно, не сломает никакие системные пакеты, а просто позволит устанавливать пакеты pip на уровне пользователя и системы. Хотя это может в редких случаях привести к конфликтам версий, обычно это не создаёт никаких проблем, особенно в случае установки Reticulum.

MacOS¶

Для установки Reticulum на macOS вам потребуется установить Python и менеджер пакетов pip.

Системы под управлением macOS могут значительно различаться в плане того, предустановлен ли Python, и если да, то какая версия установлена, а также установлен ли и настроен ли менеджер пакетов pip. Если сомневаетесь, вы можете загрузить и установить Python вручную.

Когда Python и pip доступны в вашей системе, просто откройте окно терминала и используйте одну из следующих команд:

# Установите Reticulum и утилиты с помощью pip:
pip3 install rns

# В некоторых версиях может потребоваться использовать
# флаг --break-system-packages для установки:
pip3 install rns --break-system-packages

Примечание

Директива --break-system-packages — это несколько неудачный выбор слов. Её установка, конечно, не сломает никакие системные пакеты, а просто позволит устанавливать пакеты pip на уровне пользователя и системы. Хотя это может в редких случаях привести к конфликтам версий, обычно это не создаёт никаких проблем, особенно в случае установки Reticulum.

Кроме того, некоторые комбинации версий macOS и Python требуют от вас вручную добавить ваш каталог установленных пакетов pip в переменную окружения PATH, прежде чем вы сможете использовать установленные команды в вашем терминале. Обычно добавления следующей строки в скрипт инициализации вашей оболочки (например, ~/.zshrc) будет достаточно:

export PATH=$PATH:~/Library/Python/3.9/bin

Скорректируйте версию Python и расположение скрипта инициализации оболочки в соответствии с вашей системой.

OpenWRT¶

На системах OpenWRT с достаточным объёмом памяти и хранилища вы можете установить Reticulum и связанные утилиты, используя менеджер пакетов opkg и pip.

Примечание

На момент выпуска этого руководства ведутся работы по созданию предварительно собранных пакетов Reticulum для OpenWRT с полной интеграцией конфигурации, служб и uci. Пожалуйста, смотрите репозитории feed-reticulum и reticulum-openwrt для получения дополнительной информации.

Чтобы установить Reticulum на OpenWRT, сначала войдите в сеанс командной строки, а затем используйте следующие инструкции:

# Установите зависимости
opkg install python3 python3-pip python3-cryptography python3-pyserial

# Установите Reticulum
pip install rns

# Запустите rnsd с включённым отладочным логированием
rnsd -vvv

Примечание

Приведённые выше инструкции были проверены и протестированы только на OpenWRT 21.02. Вполне вероятно, что другие версии могут потребовать немного изменённых команд установки или названий пакетов. Вам также потребуется достаточно свободного места в вашей оверлейной ФС и достаточно свободной ОЗУ для фактического запуска Reticulum и любых связанных программ и утилит.

В зависимости от конфигурации вашего устройства вам может потребоваться настроить правила брандмауэра для работы входящего и исходящего подключения Reticulum. Пока не будет готова полноценна упаковка, вам также потребуется вручную создать службу или скрипт запуска для автоматического запуска Reticulum во время загрузки.

Также обратите внимание, что AutoInterface требует включения локальных IPv6-адресов (link-local) для любых устройств Ethernet и WiFi, которые вы собираетесь использовать. Если ip a показывает адрес, начинающийся с fe80::, для рассматриваемого устройства, AutoInterface должен работать на нём.

Raspberry Pi¶

В настоящее время рекомендуется использовать 64-битную версию Raspberry Pi OS, если вы хотите запускать Reticulum на компьютерах Raspberry Pi, поскольку для 32-битных версий не всегда доступны пакеты для некоторых зависимостей. Если Python и менеджер пакетов pip ещё не установлены, сделайте это сначала, а затем установите Reticulum с помощью pip.

# Установите зависимости
sudo apt install python3 python3-pip python3-cryptography python3-pyserial

Хотя это может в редких случаях привести к конфликтам версий, обычно это не создаёт никаких проблем, особенно в случае установки Reticulum.

Хотя установить и запустить Reticulum на 32-битных ОС Raspberry Pi возможно, это потребует ручной настройки и установки необходимых зависимостей для сборки, и это не описывается в данном руководстве.

python3 -m pip install rns

Windows¶

В операционных системах Windows самый простой способ установить Reticulum — использовать менеджер пакетов pip из командной строки (CMD или Windows Powershell).

Если у вас ещё не установлен Python, загрузите и установите его. На момент публикации этого руководства рекомендуемая версия — Python 3.12.7.

Важно! При запросе установщика обязательно добавьте программу Python в переменные окружения PATH. Если вы этого не сделаете, вы не сможете использовать установщик pip или запускать встроенные служебные программы Reticulum (такие как rnsd и rnstatus) из командной строки.

После установки Python откройте командную строку или Windows Powershell и введите:

pip install rns

Теперь вы можете использовать Reticulum и все встроенные служебные программы непосредственно из предпочитаемого вами интерфейса командной строки.

Чистый Python Reticulum¶

Предупреждение

Если вы используете пакет rnspure для запуска Reticulum на системах, которые не поддерживают PyCA/cryptography, важно, чтобы вы прочитали и поняли раздел Криптографические примитивы этого руководства.

В некоторых редких случаях, на менее распространённых типах систем невозможно установить одну или несколько зависимостей. В таких ситуациях вы можете использовать пакет rnspure вместо пакета rns или использовать pip с опцией командной строки --no-dependencies. Пакет rnspure не требует внешних зависимостей для установки. Пожалуйста, обратите внимание, что фактическое содержимое пакетов rns и rnspure полностью идентично. Единственное отличие в том, что пакет rnspure не указывает зависимостей, необходимых для установки.

Независимо от того, как Reticulum установлен и запущен, он будет загружать внешние зависимости только если они нужны и доступны. Если, например, вы хотите использовать Reticulum в системе, которая не может поддерживать pyserial, это вполне возможно с использованием пакета rnspure, но Reticulum не сможет использовать интерфейсы на основе последовательного порта. Все остальные доступные модули по-прежнему будут загружаться при необходимости.
